# Vercel を見回すとき

## チーム ID を必ず付ける

Vercel の MCP は、チーム ID（`teamId`）を付けずに呼ぶと**個人の領域**を見に行く。プロジェクトがチームにあると、権限の問題ではないのに次のようになる。

| 呼び出し | チーム ID なし | チーム ID あり |
|---|---|---|
| `list_projects` | 0件 | チームのプロジェクト |
| `get_project` | 404 | 読める |
| `list_deployments` | 403 | 読める |
| `list_teams`・ドメイン | 読める | 読める |

なので、プロジェクト・デプロイ・ログ・ランタイムエラーの呼び出しには、**毎回 `teamId` を付ける**（`slug` でもよい）。

1. 見回りの最初に `list_teams` を1回呼び、チームの `id`（`team_` で始まる）を取る。チームが複数あれば、見回す対象のチームをすべて回る
2. 以降の `list_projects`・`get_project`・`list_deployments`・`get_deployment`・`get_runtime_errors`・`get_runtime_logs` などに、その `teamId` を付ける
3. チーム ID を手順やメモに書き写して決め打ちにしない（チームが変わると黙って0件になる）

## 0件・404・403 が出たとき

カードを起こす前に、次を確かめる。

1. その呼び出しに `teamId` を付けたか。付けていなければ付けて呼び直す
2. `list_teams` で、見回す対象のチームがまだ見えるか
3. 付けて呼び直しても 0件・404・403 のとき、またはチームが見えないときだけ、`inbox-card` で「確認」のカードにする。本文には、呼び出し名・付けた `teamId`・返ってきたもの（件数やステータス）・前回は読めていたか、を書く。トークンや認可の URL は書かない
