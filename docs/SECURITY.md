# セキュリティの考え方

Plasmod は、AI エージェントに VPS の上で仕事をさせ、スマホから指揮します。**エージェントは間違えるし、だまされる**前提で作っています。

## 誰が何をできるか

| | できること | できないこと |
|---|---|---|
| **オーナー** | 判断・承認（パスワード）・コマンドの実行 | — |
| **アプリ**（`plasmod` ユーザー） | 画面と API、仲介・bridge・root の仲介への依頼 | コードの書き換え。root の実行はオーナーのパスワードが無いとできない |
| **Hermes のエージェント**（`hermes` ユーザー） | 自分の作業、root 作業の依頼（設定による） | 承認 |
| **開発エージェント**（別ユーザー） | 開発、root 作業の依頼 | 承認。アプリの設定を読むこと |

## 守りの仕組み

- **入口は Tailscale だけ**。ポートを外に開けない。`Tailscale-User-Login` を信用するのは、`tailscaled` とアプリしか開けない unix ソケットから来たものだけ
- **VPS 自身からのアクセスは断る**。VPS の中のエージェントが、オーナーの名前で tailnet 越しに承認できないように
- **別のサイトからの書き込みを断る**（`Sec-Fetch-Site`・`Origin`）。Tailscale の本人確認はブラウザが自動で通るので要る
- **画面の守り**: Content-Security-Policy でスクリプトを自分のものに限り、枠の中に入れさせない
- **root の実行**: 依頼の全文と指紋（SHA-256）を見て、毎回パスワード。依頼した本人は承認できない。5回間違えると15分ロック。すべて記録に残る
- **読むだけのコマンド**（`rootreq inspect`）: 決まった項目だけ。`.env`・鍵・リンクの先は読まない。秘密らしい値を伏せる。1分60回まで
- **更新**: GitHub の署名とオーナーのアカウントを確かめてから入れる。root に関わる変更は人の承認を待つ

## 知っておいてほしいリスク

- **パスワードと Tailscale のアカウントが揃うと、root で何でもできます。** アプリの「コマンドを実行する」があるためです。使い回さないパスワードにして、Tailscale のアカウントは2段階認証で守ってください
- **Tailscale の設定に頼っています。** 許可したログインの端末を失くしたら、Tailscale から外してください
- **秘密を伏せる処理はパターンです。** 形の珍しい秘密は、ログの読み取りで見える可能性があります
- **アプリは Hermes の API キーを持ちます。** アプリのユーザーが乗っ取られると、エージェントを動かせます
- **データは暗号化していません。** `/var/lib/plasmod/` の会話・タスク・メモは平文です。端末にはメモの本文とカードの写しが残ります
- **エージェント自身の権限は Hermes と Claude Code の設定によります。** Plasmod はそこまで制限しません

## 問題を見つけたら

公開の Issue ではなく、リポジトリの Security タブの「Report a vulnerability」から知らせてください。
