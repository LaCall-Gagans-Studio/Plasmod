# オーナー宛てのタスクを登録する（受信箱）

タスクはすべてアプリにある。期限が近い・過ぎたタスクはアプリが自分で出すので、登録しなくてよい。Linear に書き込まない・Linear を見に行かない。

オーナーのアプリ（Plasmod）では、見回りで拾ったものは**まずタスクに登録し、判断待ちのタスクだけがホームのカードになる**（2026-10-24 から。以前のように `hermes kanban create --assignee owner` でカードを直接作らない）。

登録は `plasmod-task add`。**同じ元（`--source` と `--key`）は何度登録しても1件にまとまり、オーナーの判断が残る**:

タスクの状態は **判断待ち・やる・任せ中・完了** の4つ（2026-10-29 から。返事待ちは無くなった）。

| オーナーの判断 | 同じ元をまた登録すると |
|---|---|
| 完了（不要も） | 何も起きない。ただし `--event-at` が判断より新しい（新しい返信が来た等）ときは判断待ちに戻る |
| やる・任せ中 | 中身だけ更新（カードには戻らない） |
| まだ判断していない | 中身だけ更新（カードは1枚のまま） |

なので、見回りのたびに「前に出したか」を気にせず登録してよい。**`--key` を毎回同じにすることだけが大事。**
`--event-at` は「元に新しい動きがあった時刻」。毎回の見回りの時刻を入れない（済みにしたものが毎回戻ってしまう）。

## 登録する基準

登録する:
- 返信が必要かどうか、オーナーの判断が要るメール（1スレッド＝1件。ニュースレター・自動通知・明らかに不要なものは登録しない）
- ops の朝レポートで「要確認」としたもの
- 朝夜のまとめで、オーナーの判断が要る項目

登録しない:
- 自分（エージェント）が片付けられること。先に片付ける
- 1回の実行で新しく登録するのが5件を超えるとき。超える分は1件にまとめて、本文に一覧を書く（`--key` はまとめの日付など）

## 書き方（判断待ちは「問い」だけ）

判断待ちのタスクは、そのままホームのカードになる。**オーナーが読んで、すぐ決められる形**で書く:

- **題は問いの形**: 「田中商事の請求書に返信するか？」「Vercel のビルド失敗を直してよいか？」。ただの名詞（「請求書の件」）にしない
- **本文は3行から始める**:
  1. 何の話か（誰から・何が・いつまで）
  2. 選択肢（返信する／しない、など）
  3. おすすめと理由（「経理エージェントに任せるのがよい: 支払いの確認は経理の担当」）
  補足は、その下に短く。自分向けのメモ（「親: TASK-123。段2 の後」など）は書かない
- オーナーの判断が要らないこと（自分の作業・計画の段）は判断待ちにしない。`--status todo`（オーナーがやる）か `--status doing`（エージェントがやる）で登録する。自分で登録したタスクは `plasmod-task status <番号> done` で完了にできる

```bash
plasmod-task --as <自分のプロファイル名> add \
  --source mail --key "<Gmail のスレッド ID>" \
  --title "田中商事の請求書（10/31 払い）に返信するか？" \
  --kind reply --agent acct --propose kanban \
  --url "https://mail.google.com/mail/u/0/#inbox/<スレッド ID>" \
  --event-at "<スレッドの最後のメールの日時（ISO 8601）>" <<'MD'
田中商事から 10/31 払いの請求書が届いた（金額 33,000 円）。
選択肢: 経理エージェントに確認と返信を任せる／返信しない
おすすめ: 経理エージェントに任せる。支払いの確認は経理の担当
MD
```

結果は1行で返る: `登録した` / `更新した` / `変わらず` / `判断待ちに戻した` / `登録しなかった（理由）`。

### `--source` と `--key`（元の ID。揺れない値を使う）

| 元 | `--source` | `--key` | `--event-at` |
|---|---|---|---|
| メール | `mail` | Gmail のスレッド ID（件名は使わない） | スレッドの最後のメールの日時 |
| Beeper | `beeper` | `<チャット ID>:<メッセージ ID>`（同じ会話の続きなら最初のメッセージ ID） | 最後のメッセージの日時 |
| ops | `ops` | `<対象>:<問題>`（日付は付けない。例 `vercel:my-site:build-failed`、`vps:disk-usage`） | 前回のレポートから**新しく起きた・悪化した**ときだけ、今の時刻 |
| 朝夜のまとめ | `digest` | `<項目の短い名前>:<YYYY-MM-DD>` | 省略 |

**ops のキーは自分で考えるので、回ごとに言い方が変わりやすい**（例: `domain:x.com:icann-verification` → 次の回に `domain:x.com:icann-verify`）。言い方が変わると別の件として出し直され、オーナーが「不要」にしたものが再浮上する。登録の前に `plasmod-task --as <自分> list --source ops --status inbox,todo,doing,done,dismissed -n 100` で前の回のキーを見て、**同じ件なら前と同じキーをそのまま使う**。メールなど別の元で登録済みの件（例: AWS の通知メール）は、ops で重ねて登録しない。

### そのほかの項目

| 項目 | 意味 |
|---|---|
| `--kind` | `reply`（返信）／`confirm`（確認。`ops` も同じ）／`todo`（対応、既定） |
| `--status` | 新しく作るときの状態。`inbox`（判断待ち、既定）／`todo`（やる）／`doing`（任せ中）。もうあるタスクの状態は変わらない |
| `--agent` | 「任せる」を押されたときの渡し先。経理・請求・見積は経理エージェント（acct）、デザイン・資料の見た目はデザインくん（design）、開発・調査は開発エージェント（dev）、それ以外はハブのエージェント（default）。省略するとハブのエージェント |
| `--propose` | 提案（カンマ区切り）: `kanban`（`--agent` にカンバンで任せる）／`task`（オーナー自身のタスクとして残す）。カードの先頭に提案のボタンが出る。本文の最後に「提案の理由」を1〜2行 |
| `--url` | 元を開くリンク（https のみ） |
| `--project` | プロジェクト（メモと共通。分かれば） |
| `--due` | 期日（YYYY-MM-DD。分かれば） |

## メール・Beeper の扱い

- **メール（返信が要る）**: 返信の下書きを Gmail に作れたら `--kind confirm` で登録し、本文に「Gmail に下書きを作った」と要点を書く（送るのはオーナー）。作れなかったものは `--kind reply`（カードに「返信の下書きを頼む」が出る）。**送信はしない**
- **Beeper**: 見るだけ。返信が要りそうなら `--kind confirm --source beeper` で登録し、本文に返信案を書く（送るのはオーナー。Beeper のカードには返信の選択肢は出ない）

## オーナーが押したあと（ボタンは移る先の状態の名前）

- **完了／不要／返信不要**: タスクが完了になる。何も起きない
- **自分でやる**: タスクが「やる」になる（エージェントは何もしなくてよい）
- **〇〇に任せる**: `--agent` のプロファイルに、題名・本文・元・一言つきのカンバンのカードが起こされ、タスクは「任せ中」。受けたら通常どおり進める。カードを完了にすると、タスクも完了になる。止まったら（block）タスクは判断待ちに戻る
- **下書きを頼む**: ハブのエージェント（default）に「返信の下書き: 題名」のカードが起こされる。受けたら Gmail に下書きを作り（**送信しない**）、件名と要点をカードのコメントに書いて完了にする
- **あとで**: しばらく伏せる（タスクは判断待ちのまま）

## 確かめるとき

```bash
plasmod-task --as <自分> find --source mail --key "<スレッド ID>"   # 登録済みか・判断と記録
plasmod-task --as <自分> list                                      # 開いているタスク
plasmod-task --as <自分> list --status done,dismissed              # 完了したもの（dismissed は理由が不要）
```

## 注意

- 本文に、パスワード・トークン・鍵を書かない
- 登録したら、報告には「受信箱に N 件登録した（新規 X・戻した Y）」と短く書くだけにする（内容はアプリで読む）
- `plasmod-task` がエラーで使えないときだけ、以前のやり方（`hermes kanban create --assignee owner`）で起こしてよい。その場合は報告にそう書く
